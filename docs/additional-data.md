# 새 자료 추가와 모델 다시 학습하기

회사 자료는 GitHub에 올리지 않고 서버의 비공개 작업 폴더에 보관합니다. 정해진 양식의 CSV 또는 Excel(.xlsx) 파일을 추가하면 다음 전체 실행에서 읽습니다. 코드를 수정할 필요는 없습니다.

## 1. 양식 내려받기

분석 화면 왼쪽에서 `추가자료` → `양식` 폴더를 엽니다. 아래 두 파일 중 편한 것을 내려받습니다.

- `추가자료_입력양식.csv`
- `추가자료_입력양식.xlsx`

마우스 오른쪽 버튼 → Download로 내려받습니다. GitHub에서도 [빈 CSV 양식](../templates/추가자료_입력양식.csv)을 받을 수 있습니다. 양식과 폴더는 첫 전체 실행 때 자동으로 만들어집니다.

## 2. 하루에 한 행씩 작성하기

**전체 품목의 하루 집계를 한 행으로 입력합니다.** 품번별 기록이나 개별 제품 기록을 섞지 않습니다. 날짜는 기존 검사자료의 마지막 날짜 이후로 입력합니다.

| 열 이름 | 넣을 내용 |
| --- | --- |
| `날짜` | `YYYY-MM-DD` 형식의 날짜 |
| `검사수량` | 해당 날짜의 전체 검사수량. 정수로 입력 |
| `핀홀피트건수` | 같은 날짜·같은 검사 범위의 핀홀·피트 기록 건수. 정수로 입력 |
| `설정전류밀도_A_dm2` | 크롬 공정의 하루 평균 설정전류밀도. 단위 A/dm² |
| `전압_V` | 0.1V 이하 기록을 제외한 크롬 공정의 하루 평균 전압. 단위 V |
| `온도_C` | 크롬 공정의 하루 평균 온도. 단위 ℃ |
| `처리시간_초` | 크롬 공정의 하루 평균 실제 처리시간. 단위 초 |
| `에칭크롬산자동투입_ml` | 하루 자동투입 합계. 단위 ml. 모르면 빈칸 |
| `도금크롬산자동투입_ml` | 하루 자동투입 합계. 단위 ml. 모르면 빈칸 |
| `첨가제자동투입_ml` | 하루 자동투입 합계. 단위 ml. 모르면 빈칸 |

작업조건은 기존 분석과 같이 전류·면적·처리시간이 양수인 크롬 공정 기록을 기준으로 평균합니다. 전류밀도는 설정전류를 제품의 기하학적 표면적(dm²)으로 나눈 값입니다. 담당자가 원본의 열 이름·단위와 집계 범위를 확인해 정리합니다.

검사가 끝난 날짜는 `검사수량`과 `핀홀피트건수`를 함께 입력합니다. 검사 결과가 아직 없다면 **두 칸을 모두 비워 둡니다.** 이 행은 학습에 쓰지 않고 예측만 합니다. 예측용 날짜는 검사 결과가 있는 마지막 학습일 이후여야 합니다.

열 이름과 단위를 바꾸지 않습니다. CSV는 UTF-8 또는 CP949로 저장합니다. Excel은 첫 번째 시트에 이 양식을 작성합니다. 기존 회사 Excel의 서로 다른 서식은 담당자가 이 양식으로 정리한 뒤 넣습니다.

## 3. 서버에 올리고 전체 실행하기

1. 왼쪽 파일 목록에서 `추가자료` → `입력` 폴더를 엽니다.
2. 위쪽 **Upload Files** 버튼으로 작성한 CSV 또는 Excel을 올립니다. 파일을 끌어 넣어도 됩니다.
3. 노트북에서 **Run → Run All Cells**를 누릅니다.
4. 맨 아래에 **분석 완료**가 표시될 때까지 기다립니다.

파일을 여러 개 넣을 수 있습니다. 하루에 한 행만 사용하므로 파일 간에 날짜가 겹치면 중복을 정리하라는 오류가 나옵니다. 같은 자료를 CSV와 Excel로 동시에 올리지 않습니다. 양식과 빈 파일은 `입력` 폴더에 넣지 않습니다.

매번 `입력` 폴더의 모든 파일을 읽어 모델을 새로 학습합니다. 이전에 추가한 자료도 계속 반영하려면 해당 파일을 폴더에 남겨 둡니다. 검사 결과가 나중에 나오면 기존 해당 날짜 행의 `검사수량`과 `핀홀피트건수`를 채우고 다시 실행합니다.

## 4. 갱신되는 결과

전체 보고서 맨 위에 새로 추가한 자료의 분석이 표시됩니다. 상세 결과는 `분석결과/추가자료분석` 폴더에 저장됩니다.

| 결과 파일 | 내용 |
| --- | --- |
| `추가자료_분석보고서.html` | 추가자료 반영 현황, 월별 집계, 예측과 실제 결과 비교 |
| `월별_검사집계.csv` | 기존 검사자료와 추가 검사자료를 합한 월별 집계 |
| `검증결과.csv` | 나중 날짜를 따로 남겨 확인한 예측 오차 |
| `검증용_예측결과.csv` | 시험 날짜의 실제 값과 예측값 |
| `미검사자료_예측결과.csv` | 검사 결과가 아직 없는 추가자료의 예측값 |
| `핀홀피트_예측모델.joblib` | 검사 결과가 있는 자료로 다시 학습해 저장한 모델 |
| `실행정보.json` | 반영한 파일, 날짜 수, 학습 기간과 실행 성공 여부 |

검사 결과가 있는 자료를 추가하면 기존 검사자료와 합쳐 모델을 다시 학습합니다. 검사 결과가 없는 작업조건만 추가하면 기존 검사자료로 학습하고 새 날짜의 예측을 계산합니다. 모델은 작업조건이 입력된 날짜의 핀홀·피트 기록 비율을 예측하며, 개별 제품의 합격 판정이나 생산 전 경보 기능은 아닙니다.

마지막 20% 날짜는 시험용으로 따로 남깁니다. 앞선 날짜 안에서 시간순으로 모델을 비교한 뒤 시험하고, 저장할 모델은 검사 결과가 있는 모든 학습 가능 날짜로 다시 학습합니다. 빈 작업조건이 많은 기존 날짜는 학습에서 제외될 수 있습니다.

기존 원본 대조와 206일 재현 분석은 유지하며, 추가자료 분석을 별도로 계산합니다. 원본·기존 CSV·검증용 준비자료를 덮어쓰지 않습니다. 추가자료가 없으면 기존 분석만 실행합니다.

## 담당자가 확인할 서버 경로

| 분석 화면의 폴더 | 서버의 실제 위치 |
| --- | --- |
| `추가자료/입력` | `.env`의 `ROTEC_OUTPUT_DIR` 아래 `추가자료/입력` |
| `추가자료/양식` | `ROTEC_OUTPUT_DIR` 아래 `추가자료/양식` |
| `분석결과/추가자료분석` | `ROTEC_OUTPUT_DIR` 아래 `분석결과/추가자료분석` |

기본 `ROTEC_OUTPUT_DIR`은 `server-output`입니다. 이 작업 폴더와 `추가자료` 폴더는 Git에서 제외되며 Docker를 다시 만들어도 서버에 남습니다. 기존 `raw`, `csv`, `prepared`는 `ROTEC_DATA_DIR`에서 읽기 전용으로 연결합니다.
